# 验证与验收

项目没有单元测试框架。界面改动靠浏览器里能测出来的数字验证：用 Puppeteer 驱动真实页面，
读 DOM 尺寸、采样截图像素、模拟交互。

这么做的原因很直接：这里绝大多数缺陷是“看起来不对”，而看起来不对最后都能落到一个数值上，
比如对比度、位移、溢出或者帧差。

## 每次都要做

```bash
npm run build
```

构建通过不代表没坏。视觉和交互改动还要跑下面对应的项。

## 按改动类型选验证

| 改了 | 至少验证 |
|---|---|
| 颜色、遮罩、材质 | 文字对最坏背景的对比度不低于 4.5:1 |
| 布局、尺寸、响应式 | 320、375、768、1440、1920 无横向溢出，行数符合预期 |
| 交互（开关、面板） | 前后采样确认是动画过渡，不是瞬移 |
| 动画素材 | 首尾帧差接近相邻帧差，否则循环会顿一下 |
| 拖拽 | 拖起、悬停、落下三步都有效，顺序能持久化 |
| 存储 | 刷新后状态还在，坏数据不会白屏 |

## 对比度怎么测

不靠肉眼，也不靠算色值。背景是照片，所以采样截图里的真实像素。

1. 用一张高频彩色测试图做壁纸。拦截请求返回固定图片，保证结果可复现。
2. 截图。
3. 注入 CSS 把文字颜色设成 `transparent`，再截一张。
4. 在第一张里取文字盒子里最差的像素，和第二张同位置的背景色算对比度。

关键是最差像素。平均值会把问题抹平。

有个坑：测量区域要避开同一块里的不透明装饰，比如引擎 logo 和图标。
否则算出来的是“文字对图标”，这种对比并不存在，数值恒定且没有意义。

## 动画接缝怎么测

解码每一帧，只在两帧都不透明的像素上算 RGB 平均差。

```text
首帧对末帧的差，应该接近相邻帧的差
```

两者相差在 1.2 倍以内，接缝就看不出来。曾经出现过首尾差 5.89、相邻帧只有 0.25 的情况，
每循环一次就顿一下。

## 交互过渡怎么测

对会改变布局的开关，点击后每 40 毫秒采样一次目标元素的位置：

```text
216 → 177 → 154 → 146 → 143 → 141
```

单调收敛到新位置，说明动画正常。从 216 直接跳到 141 就是瞬移，要改成 `<Collapse>`。

## 验收标准

一个改动可以合并，要同时满足：

- `npm run build` 通过；
- 受影响的验证项有具体数字，不能只写“看起来没问题”；
- PR 里写明跑了什么、结果是什么；
- 引入新的取舍时，写进 `docs/` 对应页面，不要只留在对话里。
